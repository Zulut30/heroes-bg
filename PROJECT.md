# Manacost Battleground — обзор проекта

Статический веб-сайт-набор инструментов для Hearthstone Battlegrounds: конструктор стратегий, конструкторы и готовые тир-листы, библиотека существ, заклинаний и аксессуаров. Без фреймворков и сборки — чистые HTML/CSS/JS + сервлес-функции Vercel в папке `api/`. Язык интерфейса — русский, поиск работает и по английским названиям.

- **Репозиторий:** https://github.com/Zulut30/heroes-bg
- **Деплой:** Vercel (статика + `api/*` как serverless-функции, `vercel.json` не нужен — автоопределение)
- **PWA:** `manifest.webmanifest` (standalone, тема `#dbc07a`)

## Страницы

| Страница | Назначение |
|---|---|
| `index.html` | Лендинг: обзор инструментов, статистика библиотеки, ссылки на разделы |
| `strategy-builder.html` | Конструктор стратегий: полотно 5×3, быстрые слоты, аннотации (стрелки, плюсы, подписи), экспорт PNG/WebP |
| `hero-tier-builder.html` | Ручной drag-and-drop конструктор тир-листов S/A/B/C/D из героев, существ, заклинаний и аксессуаров |
| `tier-list.html` | **Тир-лист героев** по живой статистике HSReplay: галерея по тирам, среднее место под каждым героем, скачивание тиров на выбранном фоне |
| `minion-tiers.html` | **Тир-лист существ** (HSReplay): галерея по тирам S–D с цифрой Impact и скачиванием + табличный вид с винрейтом боёв, популярностью и ховер-превью карты |
| `spell-tiers.html` | **Тир-лист заклинаний** (Firestone): то же — галерея по среднему месту + таблица со статистикой |
| `library.html` | Библиотека существ с фильтрами по расе/уровню таверны, лайтбокс, экспорт выборки |
| `blizzard-spells.html` | Заклинания таверны из Blizzard API с фильтром по уровню |
| `accessories.html` | Малые и большие аксессуары, переключатель размера, экспорт выбранного |

Навигация едина на всех страницах: бренд «Manacost Battleground», дропдаун «Библиотека» (карты/заклинания/аксессуары) и прямые ссылки на тир-лист героев и оба конструктора. Логика дропдауна — `initSiteNav()` в `shared.js`.

## Общие модули

### `shared.js` → `window.Shared`
- `loadImage` / `loadImageFromSource` — загрузка картинок (HTTP с CORS и локальные пути через blob);
- `roundedRect`, `wrapText`, `drawImageContain` — примитивы Canvas;
- `maybeDownscaleCanvas` — качественный даунскейл через **pica** (WASM, фильтр mks2013), потолок 3200px;
- `compressForWordPress` — PNG→WebP через **browser-image-compression**, цель ≤1.95 МБ;
- `exportCardSheet` — экспорт сетки карточек (используется библиотекой/заклинаниями/аксессуарами);
- `loadJson`, `debounce`, `escapeHtml`, `loadBattlegroundsLibrary` (API → фолбэк `bgs-library.json`);
- `initSiteNav` — поведение дропдауна навигации.

Внешние библиотеки подключаются с CDN: `pica@9`, `browser-image-compression@2`.

### `styles.css`
Дизайн-токены в `:root`: тёмный фон `--bg #07101f`, панели с прозрачностью, золото `--gold #dbc07a` / `--gold-strong #f0d79a`, синий акцент `--accent #79b7ff`, радиусы 12–32px. Заголовки и цифры — кастомный шрифт `BgDisplay` (`font.otf`). Фон страницы — `wallpaper.jpg` с градиентными подсветками.

## Экспорт изображений (общая логика)

Все конструкторы рисуют результат на `<canvas>` и скачивают через `canvas.toBlob` → `URL.createObjectURL`:

1. **Фон** — пользователь выбирает в «пилюле» `background-picker`: «без фона» (прозрачный PNG) или один из 4 игровых обоев (`wallpaper*.jpg`). Обои рисуются с `blur(14px) brightness(0.45)` + затемняющий слой `rgba(4,8,16,0.35)`; выбор хранится в `localStorage` (свой ключ на страницу).
2. **Контент** — сетка карточек/портретов, в конструкторе стратегий поверх рисуются аннотации.
3. **Форматы** — PNG (без потерь) или WebP (q≈0.98).

## Данные и serverless-API (`api/`)

| Функция | Источник | Что делает |
|---|---|---|
| `battlegrounds-library.js` | HearthstoneJSON | Пул миньонов БГ (фильтрация, нормализация, RU+EN имена), кэш 6 ч, rate-limit 30/мин |
| `card-art.js` | art.hearthstonejson.com | Прокси арта карт с каскадом фолбэков (bgs → render → enUS → legacy), immutable-кэш, 600/мин |
| `battlegrounds-spells.js`, `blizzard-metadata.js`, `battlegrounds-card-names.js` | Blizzard Battle.net API | Заклинания, метаданные, EN-названия; OAuth-токен и общий кэш в `_blizzard.js` |
| `battlegrounds-accessories.js` | api.hs-manacost.ru + Blizzard fallback | Малые/большие аксессуары HSReplay с tier, race variants, pick rate и avg placement; Blizzard/local используются как резерв. |
| `bg-hero-stats.js` | api.hs-manacost.ru (hearthstone-parses) | Статистика героев HSReplay: тир, среднее место, pick rate; кэш 3 ч, rate-limit 30/мин |
| `bg-minion-stats.js` | api.hs-manacost.ru | Статистика существ HSReplay: impact, винрейт боёв, популярность, число игр |
| `bg-spell-stats.js` | api.hs-manacost.ru | Статистика заклинаний Firestone: среднее место (с картой и без), impact, число игр |
| `bg-comps.js` | api.hs-manacost.ru | Готовые мета-сборки HSReplay + Firestone: тир, сложность, ключевые/дополнительные карты и карты для входа в стратегию |

`_blizzard.js` — общий слой: OAuth Blizzard, кэширование, ETag/304, ограничение частоты по IP, `sendJson`.

Статические данные: `bgs-library.json` (фолбэк библиотеки), `tier-data.js` (герои для ручного конструктора), `accessories-data.js`, `hero-tiers-data.js` (см. ниже), `minion-tiers-data.js` / `spell-tiers-data.js` (снапшоты статистики + русские имена по dbfId), `comps-data.js` (снапшот мета-сборок), локальные портреты героев `heroes_bg/*.png` (114 шт., имена файлов — английские имена героев), иконки рас/таверны в `assset/`.

### Тир-листы существ и заклинаний (`minion-tiers.html`, `spell-tiers.html`)

Общий движок `card-tiers.js`: загрузка статистики (`/api/bg-minion-stats` / `/api/bg-spell-stats` → локальный снапшот), русские имена по `dbfId` из снапшота, тиры S/A/B/C/D рассчитываются квантилями по головной метрике (существа — Impact HSReplay, заклинания — среднее место Firestone; карты без метрики попадают только в таблицу). Два вида: галерея (как тир-лист героев, с фоном на каждый тир и экспортом PNG/WebP) и таблица (сортировка по колонкам, поиск RU/EN, при наведении на название — превью карты). Арт карт: в галерее напрямую с art.hearthstonejson.com (с фолбэком на `/api/card-art`), в канвас-экспорте — через `/api/card-art` (нужен CORS), поэтому экспорт существ/заклинаний работает только на деплое.

### Импорт сборок в конструктор стратегий

Блок «Готовые сборки» в сайдбаре `strategy-builder.html`: список 50+ мета-сборок HSReplay и Firestone (`/api/bg-comps` → `comps-data.js`), у HSReplay Firecrawl отдаёт тир, сложность, ключевые карты, дополнительные карты, карты «когда выходить в стратегию» и common enablers; у Firestone — тир, сложность и среднее место. Кнопка «Собрать на полотне» очищает доску (с подтверждением) и расставляет карты сборки: сперва ядро (CORE), затем дополнения, максимум 15 слотов; сопоставление с библиотекой по card id → `spell-{dbfId}` → английскому имени → русскому имени, не найденные перечисляются в статусе.

## Тир-лист героев (`tier-list.html` + `tier-list.js`)

Источник данных — агрегатор **hearthstone-parses** (https://github.com/Zulut30/hearthstone-parses), продакшен `https://api.hs-manacost.ru`, датасет `hsreplay_battlegrounds_heroes`: для каждого героя — русское имя, `dbfId`, тир S/A/B/C/D, среднее место (например «3,60»), pick rate, лучшая композиция.

Цепочка загрузки:
1. `./api/bg-hero-stats` — своя прокси-функция (у внешнего API нет CORS-заголовков, напрямую из браузера его не вызвать);
2. фолбэк — локальный снапшот в `hero-tiers-data.js` (страница работает даже без сети/API, в статусе помечается «локальный снапшот»).

Сопоставление героя с портретом: `dbfId` → карта `imageByDbfId` в `hero-tiers-data.js` (сгенерирована по HearthstoneJSON: dbfId → английское имя → файл в `heroes_bg/`). Все 114 героев имеют локальные портреты. Для героев без локального портрета используется `/api/card-art?id=…`, неизвестные новые герои получают плейсхолдер с инициалами.

Отображение: секции по тирам (S → D), внутри — галерея портретов по 6 в ряд, отсортированных по среднему месту; под каждым портретом золотая «пилюля» с числом среднего места и мелкая подпись с именем. Экспорт: каждый тир отдельно (кнопки PNG/WebP в шапке тира) или весь лист одной картинкой; фон — по той же логике, что и в конструкторе стратегий (прозрачный/4 обоев + blur и затемнение). Фон выбирается отдельно для каждого тира (пикер в шапке тира), глобальный пикер в тулбаре задаёт фон всем тирам сразу; в общем экспорте полоса каждого тира рисуется со своим фоном. Среднее место рисуется и в экспортируемой картинке.

Обновление снапшота: перегенерировать `hero-tiers-data.js` по свежему ответу API (скрипт сопоставления dbfId → файл портрета; новые герои требуют добавления PNG в `heroes_bg/`).

## Известные ограничения

- `api/*` работает только на Vercel (или `vercel dev`); при локальном статическом сервере страницы живут на фолбэках (`bgs-library.json`, `hero-tiers-data.js`), а арт через `/api/card-art` не грузится.
- Кэши функций — в памяти инстанса; на serverless это означает «тёплый» кэш только в рамках живого инстанса.
- Снапшот героев и локальные портреты статичны: при выходе новых героев нужно обновить `heroes_bg/` и перегенерировать `hero-tiers-data.js`.
- `tier-data.js` (ручные тиры героев для конструктора) обновляется вручную и может расходиться с живой статистикой `tier-list.html` — это разные источники по задумке.
